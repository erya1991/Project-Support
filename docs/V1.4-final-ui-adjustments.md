## 完成内容

| 调整 | 结果 | 主要文件 |
| --- | --- | --- |
| 帮扶关系列精简 | 业务列表、综合台账同步移除项目经理联系方式列；数据模型、详情和联系方式查询保留 | `src/utils/businessLists.js` |
| 重点工作销项区域 | 已申请只显示办结说明、佐证附件；申请时只填写这两项；未申请保留空状态。独立执行区域、项目及历史执行记录保留 | `src/views/Works.vue` |
| 诉求销项弹窗 | 使用 900px Ant Design Vue Modal；包含八项只读摘要、必填办结说明、选填附件；列表与详情共用入口 | `src/views/Appeals.vue` |
| 台账详情操作 | 五类详情底部只保留关闭，移除进入业务页面按钮及对应方法 | `src/views/Overview.vue` |
| 全部列表适配 | 所有表格取消固定横向滚动宽度，统一按相对比例转为百分比列宽，使用固定表格布局；保留业务字段和操作；长文本省略并提供 Tooltip | 六个业务视图、`businessLists.js`、`global.css`、`FileUploader.vue` |

列表和内嵌表格继续复用现有共享字段、查询逻辑及 ListQuery。全局样式仅省略单元格内的长内容，没有增加用于裁剪表格右侧字段的横向隐藏规则。表头可换行，操作链接紧凑换行，有效期内的单个日期保持完整。

实际回归还发现：重点工作从列表打开执行表单时使用了展示副本，保存后当前详情仍显示旧值。执行和销项入口现统一取原业务记录，保存后立即显示最新执行内容；未改变持久化结构、提交载荷和审批节点。

## 验证结果

- `npm run build`：通过。保留现有 Vite CJS API 弃用和大体积构建包提示，没有构建错误。
- `node scripts/check-interactions.cjs`：23 组通过。将原台账跳转断言更新为详情展示断言，补充销项必填、附件选填、反复打开、执行保存即时显示及重点工作原校验回归。
- 实际浏览器：Chromium 内嵌浏览器，视口分别为 1440×900、1920×1080。使用有数据、长文本和不同状态的业务记录，覆盖九个业务列表、五个综合台账及相关明细/编辑表格。
- [布局测量记录](screenshots/v1.4-final-ui/layout-checks.json)：42 份记录，其中 1440×900 为 20 份、1920×1080 为 22 份。页面和表格容器 `scrollWidth` 未超出 `clientWidth`；表头与首行列边界一致，状态标签、操作链接和表格控件未越出单元格；没有横向布局失败记录。
- 1440×900 下四组统计、综合台账、分页均在一屏内；切换为每页 20 条后仍正常。其他业务页保留正常纵向滚动。
- 实际展开推进计划 Tooltip，确认显示完整长文本；验证帮扶关系查询、重置和第二页连续序号，以及统计卡片筛选、台账翻页和分页容量切换。
- 五类台账详情均实际打开，底部按钮均仅为关闭。
- 诉求销项：空办结说明被阻止；取消重开清空未提交草稿；从详情打开时仅一个可见弹窗和遮罩，取消后可见遮罩数为 0。
- 独立本地测试源 `127.0.0.1:5175` 中，诉求无附件提交成功，依次通过项目经理确认、企划归档，状态回写为已销项；原销项信息、审批记录及关联日报仍显示。重点工作缺办结说明、缺佐证附件均被阻止，执行内容保存后即时显示复测通过。
- 浏览器记录的控制台错误数为 0。测试未清空现有演示数据，提交和审批验证使用独立端口的 localStorage。
