**版本：** V1.6

**用途：** 前端原型修改、研发需求交底、业务验收  
**项目：** Project-Support / 服务项目模块  
**技术背景：** 沿用现有 Vue2 + Ant Design 前端原型

# 一、版本目标与范围

## 1.1 业务目标

完善总部人员与基层项目的帮扶关系，建立企划部统一维护的部门重点工作及项目执行情况填报机制；日报根据有效帮扶关系确定填报人员；同时调整基层诉求、制度改进建议及工作总览。

## 1.2 优先级

| 优先级 | 模块 | 主要交付 |
|---|---|---|
| P0 | 帮扶关系管理 | 部门级、项目级两种帮扶关系 |
| P0 | 部门重点工作 | 企划部统一管理、个人视角、项目执行情况 |
| P0 | 日报管理 | 关联帮扶关系、调整字段 |
| P1 | 基层诉求办理 | 全员提交、审批时指派承办人、销项审批 |
| P1 | 制度改进建议 | 全员提交、主责部门经理审批 |
| P1 | 工作总览 | 统计卡片、综合台账同步调整 |

本次要求六个模块及总览一次性整体实施。P0/P1 仅表示业务优先级，不代表拆成多轮交付。

## 1.3 范围边界

- 沿用现有 Vue2 + Ant Design、路由、组件、目录结构及 UI 风格。
- 本次只做前端原型和模拟交互，不实现真实后端、数据库、审批引擎或消息推送。
- 不重新搭建项目，不迁移框架，不重构无关模块。
- 部门重点工作不设置销项流程。
- 日报继续每日填写，不改成每人每周一份。
- 日报、周报原有 Excel 导出模板保持不变。
- 不主动增加本文件未提出的业务功能。

# 二、帮扶关系管理

## 2.1 业务定位

帮扶关系是总部人员开展基层服务工作的基础配置。由企划部统一录入，无审批。

支持两种帮扶对象：

- **部门级：** 总部人员 → 分公司 → 部门 → 部门经理。
- **项目级：** 总部人员 → 分公司 → 项目 → 项目经理。

两种关系共用一个管理模块，通过帮扶对象类型区分。

## 2.2 列表字段

| 字段 | 说明 |
|---|---|
| 总部帮扶人员 | 总部人员姓名 |
| 工号、职务、总部所属部门 | 根据人员自动带出 |
| 帮扶对象类型 | 部门 / 项目 |
| 所属分公司 | 对应分公司 |
| 帮扶部门 | 部门级关系展示 |
| 帮扶项目 | 项目级关系展示 |
| 对应负责人 | 部门经理 / 项目经理 |
| 联系方式 | 对应负责人联系方式 |
| 帮扶状态 | 启用 / 停用 |
| 操作 | 编辑、启用/停用、查看历史 |

## 2.3 新增/编辑字段及交互

| 字段 | 必填 | 规则 |
|---|---|---|
| 总部帮扶人员 | 是 | 单选总部人员，自动带出工号、职务、部门、联系方式 |
| 帮扶对象类型 | 是 | 部门 / 项目 |
| 所属分公司 | 是 | 选择分公司 |
| 帮扶部门 | 条件必填 | 部门类型显示 |
| 帮扶项目 | 条件必填 | 项目类型显示 |
| 对应负责人 | 自动 | 部门经理或项目经理 |
| 联系方式 | 自动 | 对应负责人联系方式 |
| 帮扶状态 | 自动 | 新增默认启用 |

先选择总部人员，再选择类型、分公司和部门/项目；根据所选对象自动带出负责人。

## 2.4 业务规则

1. 企划部负责新增、编辑、启用和停用，不设置审批。
2. 一名总部人员可以关联多个分公司部门或项目。
3. 一个部门或项目可以关联多名总部帮扶人员。
4. 部门级、项目级关系分别记录。
5. 停用关系不删除历史记录。
6. 只有有效项目级帮扶关系参与重点工作项目匹配。
7. 日报填报资格根据有效帮扶关系确定，日报可选项目根据有效项目级帮扶关系获取。

查询支持总部帮扶人员、工号、总部部门、帮扶对象类型、分公司、部门/项目、状态。

保留历史记录，记录新增、编辑、启用、停用的时间和操作人。

# 三、部门重点工作

## 3.1 业务定位与页面视角

部门重点工作调整为企划部统一维护的常态化工作事项。不再由各部门创建梳理单，不设置牵头人，不设置销项流程。

分为两个视角，共用同一套事项及项目执行情况数据：

**企划部视角：重点工作管理**
- 统一维护事项。
- 查看全部事项及项目落实进展 C/D。
- 进入详情查看各项目执行情况。
- 导出事项和项目执行情况。

**帮扶人员视角：我的重点工作**
- 查看本人关联项目需要填写的全部启用事项。
- 区分待填写、已填写。
- 填写、编辑和查看执行情况。

## 3.2 重点工作事项

| 字段 | 必填 | 说明 |
|---|---|---|
| 所属体系 | 是 | 例如生产、经营 |
| 归属部门 | 是 | 总部部门 |
| 重点工作名称 | 是 | 事项名称 |
| 重点工作内容 | 是 | 具体描述 |
| 状态 | 是 | 启用 / 停用 |
| 创建时间、创建人 | 自动 | 系统记录 |

企划部可以新增、编辑、启用、停用、查询、导出和查看执行情况。不设置牵头人。

## 3.3 项目执行情况生成规则

一个启用的重点工作事项，关联当前所有有效项目级帮扶关系覆盖的项目：

- 不区分总部帮扶人员所属部门。
- 所有有效项目级帮扶关系参与匹配全部启用事项。
- 部门级帮扶关系不直接生成项目执行记录。
- 项目按项目主数据去重。
- 一个「重点工作事项 + 项目」只对应一条执行情况记录。
- 同一项目有多名帮扶人员时，共享同一条记录，均可查看、填写和编辑。

示例：

| 总部人员 | 总部部门 | 帮扶项目 |
|---|---|---|
| 张某 | 工程管理部 | X、Y 项目 |
| 李某 | 安全生产部 | Z 项目 |

如果有产值计划、计划节点、项目策划、安全策划四个启用事项，则 X、Y、Z 三个项目都需要填写这四项，不按事项归属部门过滤。

## 3.4 项目执行情况字段

| 字段 | 说明 |
|---|---|
| 重点工作事项 | 关联事项 |
| 项目、所属分公司 | 关联项目及其所属分公司 |
| 项目落实情况 | 帮扶人员填写 |
| 相关附件 | 可选 |
| 填报状态 | 待填写 / 已填写 |
| 首次填报人、首次录入时间 | 自动记录 |
| 最后修改人、最后修改时间 | 自动记录 |

## 3.5 企划部视角

### 事项列表

| 字段 | 说明 |
|---|---|
| 所属体系 | 事项所属体系 |
| 归属部门 | 事项所属部门 |
| 重点工作名称 | 事项名称 |
| 项目落实进展 | C/D |
| 状态 | 启用 / 停用 |
| 操作 | 编辑、启用/停用、详情 |

列表不展示冗长的项目执行内容。

### 事项详情

展示事项基本信息、C/D 进度及多条项目执行情况。

明细字段：

- 所属分公司。
- 项目名称。
- 帮扶人员。
- 项目落实情况。
- 填报状态。
- 首次填报人及录入时间。
- 最后修改人及修改时间。
- 查看详情。

### C/D 口径

- C：已填写有效项目执行情况的项目数量。
- D：当前有效项目级帮扶关系覆盖的项目总数量。
- 项目按项目主数据去重。
- 同一项目多名帮扶人员只计一次。
- 某项目的最后一条有效帮扶关系停用后，该项目不再计入 D；历史执行记录保留。
- 停用事项不参与当前启用事项的进度统计。

例如 X、Y、Z 三个有效帮扶项目中，X、Y 已填写，Z 未填写，显示 2/3。

### 导出

支持 Excel 导出，包含所属体系、归属部门、重点工作名称、项目、分公司、帮扶人员、项目落实情况、填报状态、录入时间、最后修改时间；支持按当前查询条件导出。

## 3.6 帮扶人员个人视角

新增「我的重点工作」入口，不能仅将企划部列表增加人员筛选。

个人页面生成逻辑：

1. 获取当前登录人员所有有效项目级帮扶关系。
2. 获取本人关联项目。
3. 获取全部启用的重点工作事项，不按总部部门过滤。
4. 对每个事项匹配本人关联的全部项目。
5. 读取对应的项目执行情况，显示待填写或已填写。

示例：张某关联 X、Y 两个项目，启用事项有产值计划、计划节点、项目策划，则个人视角展示 6 条「事项 + 项目」任务。

页面统计：
- 应填报项目数。
- 已填写项目数。
- 待填写项目数。

筛选：
- 全部事项。
- 待填写。
- 已填写。
- 按重点工作名称、项目名称、归属部门查询。

点击待填写进入表单，填写项目落实情况及附件；保存后同步更新个人状态、企划部 C/D 和其他帮扶人员共享的记录。已填写记录允许编辑。

## 3.7 动态变化规则

| 变化 | 个人视角 | 历史记录 |
|---|---|---|
| 新增重点工作 | 所有有效项目帮扶人员出现对应待填任务 | 保留 |
| 编辑事项 | 更新展示内容 | 已填记录保留 |
| 停用事项 | 不再展示该事项 | 不删除 |
| 重新启用事项 | 恢复对应任务，已填记录继续显示 | 不重复创建 |
| 新增项目帮扶关系 | 对应人员增加该项目的任务 | 不影响其他项目 |
| 停用项目帮扶关系 | 不再要求该人员填报该项目 | 不删除历史记录 |
| 同项目增加第二名帮扶人 | 共享已有记录 | 不重复统计 |

注意：事项详情 C/D 按项目统计；工作总览全部事项的总进度按「事项 + 项目」组合统计，不能把不同事项下同一项目合并为一条。

# 四、日报管理

## 4.1 业务定位

日报继续每日填写。本次只调整填报资格关联及部分字段，不改为每人每周一份，不重构原有日报页面。

## 4.2 填报人员范围

只有在帮扶关系中配置的总部人员，才具备日报填报资格。

- 有效帮扶关系驱动日报填报资格。
- 没有有效帮扶关系的人员不生成日报填报任务。
- 帮扶关系停用后，不再生成后续日报任务。
- 历史日报保留。
- 自动生成的是填报资格/待填任务，不是自动创建空白日报记录。

## 4.3 字段调整

| 字段 | 调整 | 规则 |
|---|---|---|
| 填报日期 | 保留 | 原每日填报方式 |
| 填报人 | 保留 | 自动带出 |
| 所属分公司 | 新增展示 | 根据所选帮扶项目带出 |
| 所属项目 | 改名 | 改为「帮扶项目」 |
| 项目层面服务需求 | 修改 | 改为手动录入 |
| 诉求事项 | 删除 | 不再展示和填写 |
| 是否到岗 | 保留 | 原规则 |
| 当日工作开展情况 | 保留 | 原规则 |
| 今日需协调问题 | 保留 | 原规则 |
| 附件 | 保留 | 原规则 |

项目层面服务需求由帮扶人员根据实际情况手动录入，不再从基层诉求或其他模块关联。

帮扶项目从当前人员有效项目级帮扶关系中选择，选择后展示所属分公司。

## 4.4 页面范围

保留原有：
- 我的日报。
- 全部日报。
- 周度汇总。

尽量不改变原有列表、填报弹窗、详情和每日填报交互。仅调整填报资格、帮扶项目、分公司展示、服务需求录入方式及删除诉求事项。

## 4.5 导出

日报、周报原有 Excel 导出模板保持不变，不重新设计模板。诉求事项不再产生新业务数据，历史数据保留。导出继续兼容原模板。

# 五、基层诉求办理

## 5.1 业务定位

公司全体人员均可提交基层诉求。提交人选择主责总部部门；主责部门经理审批时选择承办人；承办人处理后提交销项，由主责部门经理审批。

## 5.2 提交字段

### 项目、分公司人员

自动带出发起人、所属分公司、所属部门/项目。

### 总部人员

手动选择所属分公司、所属部门/项目。

两类发起人均填写：

| 字段 | 规则 |
|---|---|
| 诉求标题 | 必填 |
| 诉求内容 | 必填 |
| 主责部门 | 必填，选择总部部门 |
| 附件 | 选填 |

提交时不填写承办人；删除协同部门、推进计划、预计完成时间。

## 5.3 审批与承办人指派

提交后进入管理平台现有流程引擎，由对应主责总部部门经理审批。

部门经理审批时：
- 查看诉求信息。
- 审批是否受理。
- 选择承办人。
- 承办人从全公司人员范围内选择。

审批通过后承办人办理；退回按现有流程引擎机制处理。

## 5.4 销项

承办人提交销项申请：

| 字段 | 必填 | 规则 |
|---|---|---|
| 完成情况 | 是 | 描述实际处理结果 |
| 完成时间 | 是 | 默认当前日期，可修改 |
| 佐证附件 | 否 | 支持上传 |

由主责部门经理审批销项。通过后正式销项；不通过退回承办人继续处理。

不考虑企划部自动抄送。不另行开发审批引擎，只呈现表单、节点和模拟交互。

# 六、制度改进建议

## 6.1 提交范围与字段

公司全体人员可以提交。

| 字段 | 规则 |
|---|---|
| 建议标题 | 必填 |
| 建议类型 | 沿用原有分类 |
| 建议内容 | 必填 |
| 发起人 | 自动带出 |
| 所属分公司 | 自动带出 |
| 所属部门/项目 | 自动带出 |
| 主责部门 | 提交人手动选择总部部门 |
| 附件 | 选填 |

删除独立的「部门负责人」字段。

## 6.2 审批回复

由主责总部部门经理审批。

| 字段 | 规则 |
|---|---|
| 回复建议 | 单选：改 / 不改 |
| 回复说明 | 说明采纳或不采纳原因 |
| 计划完成时间 | 选择改时显示，非必填 |
| 回复人 | 自动带出 |
| 回复时间 | 自动记录 |

选择改时显示计划完成时间；选择不改时隐藏。回复后提交人可以查看结果。

不增加制度修订实施跟踪和验收流程。

## 6.3 页面

保留原有列表、详情、新增和回复交互，调整全员提交权限、发起人组织信息、主责部门选择、部门负责人字段及回复动态字段。

# 七、工作总览

## 7.1 设计原则

所有业务模块调整必须同步反映在总览。保留原有统计卡片、综合台账、页签切换、单号进入详情、分页和查询，不重做总览整体布局。

## 7.2 统计卡片

| 卡片 | 统计内容 |
|---|---|
| 帮扶关系 | 有效部门级帮扶数量、有效项目级帮扶数量 |
| 部门重点工作 | 启用事项总数、项目执行进度 |
| 基层诉求 | 待审批、办理中、待销项审批、已销项 |
| 日报管理 | 今日应填报人数、今日已填报人数 |

日报统计只统计具备有效日报填报资格的总部人员，并按人员去重。

重点工作总进度按「事项 + 项目」组合统计：
- C：已填写的事项-项目执行记录数。
- D：当前启用事项关联的事项-项目记录总数。

## 7.3 综合台账页签

1. 基层诉求。
2. 部门重点工作。
3. 项目执行情况。
4. 日报。
5. 制度改进建议。

字段：

**基层诉求：** 单号、诉求标题、发起人、所属分公司、所属部门/项目、主责部门、承办人、当前状态、提交时间。

**部门重点工作：** 所属体系、归属部门、重点工作名称、项目落实进展 C/D、状态。

**项目执行情况：** 重点工作事项、所属分公司、项目名称、帮扶人员、填报状态、录入时间。

**日报：** 填报人、所属分公司、帮扶项目、填报日期、是否到岗、当日工作开展情况。

**制度改进建议：** 建议编号、建议标题、发起人、所属分公司、所属部门/项目、主责部门、回复结果、当前状态。

## 7.4 交互

- 点击统计卡片，在当前页面切换综合台账对应页签并执行查询。
- 点击综合台账单号或业务标题进入对应详情。
- 详情页不显示「进入业务」按钮。
- 保留分页。
- 列表不允许横向滚动，长文本省略并悬停展示。
- 按当前用户权限展示对应数据。

# 八、统一 UI 与交互规范

- 沿用现有管理平台布局、Vue2 + Ant Design 组件及视觉风格。
- 不改变现有页面整体框架。
- 列表一屏展示字段，不允许横向滚动。
- 长文本省略展示，鼠标悬停展示完整内容。
- 保留分页。
- 结构化字段支持查询，关键文本支持模糊查询。
- 必填项明确标识。
- 自动带出字段不可随意修改。
- 关联字段按前置选择动态展示。
- 按角色和业务状态展示操作。
- 使用统一弹窗，不使用浏览器原生 alert、confirm。
- 已填写、待填写状态明确。
- 停用不删除历史记录。
- 不无必要增加子模块、状态或复杂权限。

## 9.1 模拟数据

重点工作至少覆盖：
- 多个总部部门、重点工作事项、分公司和项目。
- 一名帮扶人员关联多个项目。
- 多名帮扶人员关联同一项目。
- 部分执行记录已填写、部分待填写。
- 事项启用、停用、重新启用。
- 新增和停用帮扶关系后的个人任务变化。

日报至少覆盖：
- 有效帮扶关系人员。
- 无帮扶关系人员。
- 一人关联多个项目。
- 不同分公司项目。

基层诉求、制度建议准备不同发起组织、主责部门和审批状态。

## 9.2 验收场景

**帮扶关系：**
- 新增部门级帮扶，正确关联分公司及部门经理。
- 新增项目级帮扶，正确关联分公司及项目经理。
- 一人关联多个项目。
- 多人关联同一项目。
- 停用关系后状态更新、历史记录保留。

**部门重点工作：**
- 新增事项后，所有有效项目帮扶人员出现对应待填任务。
- 个人视角展示本人项目的全部启用事项，不按总部部门过滤。
- 填写后正确保存内容、填报人及时间。
- 同一项目多个帮扶人员共享一条执行记录。
- 编辑后更新修改人及修改时间。
- 企划部 C/D 正确。
- 停用事项后个人视角隐藏，历史记录保留。
- 重新启用后恢复任务并沿用历史记录。
- 新增项目帮扶关系后自动增加对应任务。
- 停用最后一条项目帮扶关系后，该项目不再计入当前有效进度。
- 导出事项及项目执行情况正确。

**日报：**
- 有效帮扶人员进入填报范围，无有效帮扶关系人员不进入填报范围。
- 帮扶项目选择正确，所属分公司正确展示。
- 项目层面服务需求支持手动录入。
- 不再展示诉求事项。
- 每日填报方式正常。
- 日报、周报导出模板不变。

**基层诉求：**
- 项目、分公司人员自动带出组织信息。
- 总部人员可手动选择分公司及部门/项目。
- 提交只选择主责部门。
- 部门经理审批时可选择全公司承办人。
- 承办人可提交销项。
- 部门经理可审批销项。

**制度建议：**
- 普通员工可提交。
- 组织信息正确展示。
- 主责部门可选择。
- 改/不改动态字段正确。
- 回复结果可查看。

**工作总览：**
- 帮扶关系统计准确。
- 重点工作 C/D 准确。
- 基层诉求统计与业务状态一致。
- 日报统计仅包含具备填报资格的人员。
- 点击卡片正确切换台账页签并查询。
- 点击单号或标题进入正确详情。

## 9.3 研发交接重点

后续真实研发的数据关系建议：

- 帮扶关系：总部人员 + 帮扶对象类型 + 分公司 + 部门/项目 + 状态。
- 重点工作事项：体系 + 归属部门 + 工作内容 + 状态。
- 项目执行情况：「重点工作事项 + 项目」作为唯一业务组合。
- 执行情况与帮扶人员关联，用于确定填报及查看权限。
- 日报填报资格通过有效帮扶关系确定，日报仍按原有日期维度管理。
- 基层诉求和制度改进建议使用管理平台现有流程引擎。

## 9.4 待研发确认事项

以下事项不应被 Codex 擅自编造成已确认业务规则：

1. **仅有部门级帮扶关系的人员是否生成日报：** 日报资格已明确与帮扶关系关联，但日报需要选择具体帮扶项目。对于只有部门级帮扶、没有项目级帮扶关系的人员，是否生成日报尚未最终确认。原型不要为其生成无项目可选的日报任务，并在实施结果中保留待确认说明。
2. **同一项目多名帮扶人员：** 一个「重点工作事项 + 项目」只保留一条执行记录，多名帮扶人员共享。
3. **历史执行记录与停用关系：** 停用关系或事项不删除历史数据；当前填报视图和统计范围根据有效关系及启用状态动态调整。
4. **日报导出兼容：** 日报表单删除诉求事项，但日报、周报原有 Excel 导出模板保持不变。研发需确认旧字段在导出模板中的兼容处理。
5. **审批引擎：** 基层诉求及制度建议使用管理平台现有流程引擎，不在本模块新建审批机制。
