## 实测结果

| 验收项 | 实际操作和结果 |
|---|---|
| 共享执行与统计 | 两个事项、两个项目，甲帮扶 X/Y，乙帮扶 X。甲填 A-X 和 B-Y 后，两事项各为 1/2，总览 2/4；甲个人已填事项为 0，乙为 1。乙修改 A-X 后首次填报人仍为甲。停用最后一条 X 关系后总览为 1/2，恢复后为 2/4。两个浏览器标签页分别选人，已打开的执行详情能收到另一页保存的内容。 |
| 日报与本地存储 | 一个工作日、一个人、两个分公司的项目，仅出现一份待填。取消未落库，提交和修改后仅一条；两个项目均能查到该日报。附件、管理员修订原因、历史快照、周末零任务和次日冻结通过验证。旧版模拟缓存替换一次，刷新保留新版录入，其他存储键保留。 |
| 基层诉求 | 分公司和项目发起自动带出组织，总部发起手选。实际走通受理退回、原单修改重提、跨组织选承办人、申请销项、销项退回和最终批准。完成日期和批准时间分别保存，佐证及各轮意见可查。 |
| 制度建议 | 项目员工提交后，演示者可直接办理经理回复。选“改”允许日期为空；从“改”切回“不改”后日期清除。回复人、说明和结果在业务详情及总览一致。 |
| 总览和页面 | Chrome 打开六个业务模块及独立个人入口，点击 10 个统计指标，核对目标页签、查询结果与记录数；第二页再次点击指标回到第一页。1440×900 和 1920×1080 共测量 32 个列表、台账和详情布局，均无横向溢出，总览分页在视口内。验证了长文本悬停、详情和待办跳转。 |
| 实际 Excel 文件 | 用相同的人日数据，从 V1.4 和 V1.6 各下载日报及周报。解析实际文件后，工作表名、范围、表头列序、行高、列宽、合并区域、样式定义和各单元格样式一致。日报原项目列显示两个项目；周报合并区首格包含两个日期的手录需求。筛选单个事项后下载的重点工作 Excel 含两个项目及正确的首次、最后填报人。 |

[交互回归](../scripts/check-interactions.cjs) 共 11 组通过，`npm run build` 和 `git diff --check` 均通过。构建有 Vite CJS API 弃用及主包体积提示。项目未配置独立 lint 或 typecheck 命令。

负责人业务验收和部署尚未执行。正式业务需确认仅有部门级帮扶关系人员的日报资格，本版采用已确认的原型口径，暂不生成此类任务。
